What it does

What website integration does

A website integration connects a web application with TallyPrime. The web application can be a company website, a customer portal, a dealer portal or a B2B ordering site.

The integration sends approved records from the portal to TallyPrime. It can also send selected TallyPrime data back to the portal. For example, a dealer can see an invoice or an outstanding balance after login.

The web application does not connect to TallyPrime directly in most designs. A middleware layer receives the portal request, checks it and sends it to TallyPrime in a supported format.

Who needs it

  • Businesses whose customers place orders on the business website, and that want each order to go directly into TallyPrime without re-entry.
  • Manufacturers that take orders from dealers or distributors through a portal.
  • Distributors that want customers to see invoices, statements or outstanding balances.
  • Businesses with a custom web application that creates sales, receipts or service records.
  • Teams that copy portal records into TallyPrime by hand today.

Practical workflow

Example: a customer places an order on your website

This example shows one possible design. Your steps can be different.

  1. 01

    Your customer selects items on your website and places the order. The website gives the order a unique order reference.

  2. 02

    The integration receives the order. It checks the customer, the item codes, the quantities, the prices and the tax fields.

  3. 03

    The integration maps each website field to the related TallyPrime ledger, stock item and voucher type, as given in the approved mapping rules.

  4. 04

    The integration creates the order in TallyPrime, for example as a sales order or a sales voucher, as the approved rules specify. Your team does not type the order again.

  5. 05

    TallyPrime updates the stock and the customer's ledger. Your accounts team sees the new entry with the website order reference.

  6. 06

    If a check fails, the integration does not create the entry. It holds the order, logs the reason, and shows the order to your team for review.

Mapping, validation and errors

Controls that keep the data correct

Mapping

Map each portal field to a TallyPrime field. Map portal customer IDs to ledger names and item codes to stock items.

Validation

Reject an order with an unknown dealer, an inactive item, a missing GSTIN or a price outside the agreed rule.

Error handling

Keep a failed request in a queue. Show the reason to your admin team. Do not create a partial entry.

Access control

Show each portal user only their own records. Keep TallyPrime access details on the server side, not in the browser.

Website integration questions

Frequently Asked Questions

Can a dealer portal show live balances from TallyPrime?

A portal can show balances from TallyPrime when the design allows a regular data update. The update interval depends on your TallyPrime setup and the agreed design. We confirm this during the feasibility review.

Does TallyPrime need to run all the time for website integration?

Most designs need TallyPrime, or a TallyPrime server, to be available when the integration runs. A queue can hold portal requests when TallyPrime is not available. The queue sends them when the connection is available again.

Can the portal create invoices directly in TallyPrime?

It is possible in some workflows. Many businesses send orders first and create invoices in TallyPrime after approval. Your team decides which records the portal can create.
